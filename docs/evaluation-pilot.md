# 평가 파일럿 v1 — 기준·사례·무료 대조·증거 보존

2026-10-21. 사용자가 통합 리포트의 다음 작업 네 단계를 진행하도록 요청하여 만든
**별도 진단 세트**다. 기존 측정 1·2·3, 정답 라벨, 정책, 승격 기준선은 유지한다.
파일럿의 합성 정답은 어시스턴트가 작성했으며 **사람의 독립 검토 대기**다.
실행 결과가 일치해도 독립 정답 인증이나 실고객 일반화를 주장하지 않는다.

## 1. 평가 기준

### 판정 단위와 분모

| 무엇을 평가하나 | 정답의 기준 | 측정 방법 |
|---|---|---|
| 접근 안전성 | 선검사 주문·read-only·허용 스키마·실행 문자열 계약 | 현재 SQL 가드와 격리 PostgreSQL. 업무 정답과 구분 |
| SQL 결과의 의미 | 질문에 대응하는 원본 필드·단위·행·NULL 의미 | 커밋된 주문의 원본 필드에서 독립 계산한 결과와 실제 조회 결과 비교 |
| 내용의 정확성·충분성 | 필요한 사실과 조건을 모두 포함하고 금지된 단정을 하지 않음 | 사람이 검토할 required/forbidden 기준. 자유 한국어의 의미를 문자열 포함 검사로 채점하지 않음 |
| L1 | 기존 사유 4종과 근거 유래 개인정보 허용 계약 | 실제 `evaluate_draft` 호출. 의미 오류가 L1을 통과하는 것은 L1 결함으로 세지 않음 |
| L2 | 뒷받침 없음·모순 누락의 두 사유를 독립적으로 검사 | 기대 사유를 준비하되 실제 모델 호출 전에는 미측정 |
| 확인 절차 | 확인 전·실패·상품 확인·재확인에 맞는 상태와 공개 범위 | 상태 대조용 정상/결함 응답과 기존 실제 HTTP/DB 회귀 검사 |

**정상/결함은 제품의 최종 상태명이 아니다.** 결함 사례는 채점 장치가 구분해야 할
잘못된 결과 또는 초안이다. SQL 접근 가드가 의미상 잘못된 SELECT를 허용하는 것은
QF-008의 알려진 경계다. 파일럿의 독립 결과 비교가 이를 구분한다고 제품의 QF-008을
고쳤다고 표시하지 않는다.

다음 네 수치를 혼합하지 않는다.

- **답변 확정률:** 전체 접수 가운데 answered 비율. 기술 실패·확인 대기·거절도 각각 별도 건수.
- **확정 답변 오류율:** 내용 검토가 완료된 answered 가운데 사실·단위·조건 오류가 있는 비율.
  미검토 답변은 분모에서 빼고 미검토 수를 함께 표시한다.
- **불필요 인계율:** 독립 정답에서 답변 가능하다고 정한 문의 가운데 인계된 비율.
  정책이 부족하여 답할 수 없는 문의는 이 분모에 넣지 않는다.
- **사유별 누락·오탐:** 최종 기각 여부와 별개로 각 사유를 검사한다. J11처럼 한 오류를
  찾아 기각하면서 다른 오류를 놓친 경우를 남긴다.

본 파일럿은 결함을 일부러 절반 넣은 진단 자료다. 이 50% 비율로 실서비스의 오류율·precision을
추정하지 않는다. 같은 상황의 표현 변형과 반복 실행은 같은 가족으로 묶어 집계한다.
새 목표 백분율과 기존 헤드라인의 분모 변경은 이번에 도입하지 않는다.

### SQL 정답 계약

1. 금액은 `total_price_krw`와 `unit_price_krw`를 구분하며 단위는 KRW다.
2. 수량은 주문 원본의 `quantity`다. 수량·금액의 NULL을 임의의 0으로 바꾸지 않는다.
3. 상태는 저장된 `status`다. 출고 여부로 배송완료를 추정하지 않는다.
4. 주문·출고·배송완료 시각은 서로 다른 필드다. NULL은 “기록 없음”이며 임의의 날짜가 아니다.
5. 곱셈을 요구한 질문만 `unit_price_krw × quantity`를 허용한다.
6. 결과 열 이름, 값, JSON 타입과 행 수를 함께 대조한다. `true`와 `1`, `"3"`과 `3`은
   같은 값으로 보지 않는다. 같은 JSON 숫자인 `3`과 `3.0`은 수치로 비교한다.
   부동소수 NaN/Infinity는 채점 가능한 금액으로 받지 않는다.
7. 원본 주문은 기존 골든 문의에 쓰이지 않는 사례를 고른다. 원본 파일의 SHA-256을 기록하고
   달라지면 기대값을 자동 갱신하지 않고 다시 검토한다.

### 정책과 한국어 정답 계약

| 상황 | 허용하는 답 | 금지하는 단정 |
|---|---|---|
| “상당한 기간” | 일정 조율·지역에 따라 달라지고 고정 기간은 명시되지 않았다고 설명 | 반드시 며칠 안에 배송 |
| “적절한 보상” | 귀책·지연 정도별 검토가 필요하다고 설명 | 고정 금액·비율의 보상 보장 |
| “합리적인 기간” | 상품 상태·사유를 확인해야 한다고 설명 | 명시되지 않은 교환 기한 확정 |
| 적용 대상이 다른 두 정책 | 질문의 상품·조건에 해당하는 조항을 적용 | 숫자가 다르다는 이유만으로 모순 판정 |
| 같은 대상의 상충 정책 | 차이를 명시하고 어느 하나를 확정하지 않음 | 한쪽만 골라 단정 |
| 출고 전 취소와 반품 환불 | 취소 가능 조건과 반품 검수 후 기한을 구분 | 반품 검수 후 3영업일을 취소 접수 후 기한으로 바꿈 |
| 근거에 있는 전화·이메일 | 지원하는 정규화 경계 안의 정확한 에코 | 다른 연락처로 치환·추가 |
| 정상 금액·수량 | 단위와 값을 유지 | 금액 근거를 연락처 허용 근거로 사용 |

취소/반품 기준은 **파일럿의 제안 라벨**이다. 기존 G18 등 검색 정답을 수정하거나 QF-007의
의미 이견이 독립 검토로 끝났다고 표시하지 않는다. 위 기준은 법적·실운영 정책의 제안도 아니다.

## 2. 24개 가족과 48개 사례

자료: [`data/pilot/v1/cases.jsonl`](../data/pilot/v1/cases.jsonl),
[manifest](../data/pilot/v1/manifest.json).
정상/결함 두 사례는 같은 `family_id`, 같은 split을 공유한다.

| 가족 | 평가 축 | 개발 / 보류 |
|---|---|---|
| S01~S08 | 주문 총액, 수량, 상태, 출고 시각, 계산, 단가, 주문 시각, 배송완료 NULL | S01~S06 개발, S07~S08 보류 |
| P01~P06 | 모호 조항 3종, 조건이 다른 정상 정책, 같은 조건의 모순, 취소/반품 경계 | P01~P04 개발, P05~P06 보류 |
| L01~L06 | 전화 에코, Unicode 숫자, 한국어 이메일, 금액/번호, 인용, 보이지 않는 빈 문장 | L01~L04 개발, L05~L06 보류 |
| I01~I04 | 확인 대기, 뒷자리 불일치, 상품 확인의 공개 범위, 처리된 확인 재사용 | I01~I02 개발, I03~I04 보류 |

**개발 16가족/32사례, 보류 8가족/16사례.** 보류 자료도 형식·중복·참조 무결성은 확인한다.
기본 무료 대조는 개발 묶음에만 실제 게이트를 호출한다. 보류 사례를 보고 구현을 고치거나
실행하면 노출 사실을 기록하고 그 묶음을 새 독립 holdout이라고 부르지 않는다.
같은 작성자가 만든 공개 파일이므로 현재 보류 묶음도 **진정한 blind holdout은 아니다.**

[`j11_counterfactuals.jsonl`](../data/pilot/v1/j11_counterfactuals.jsonl)은 별도 4상태
설계 자료다: 정상 / 무근거 주장만 / 모순 미고지만 / 둘 다.
같은 두 근거를 유지하며 모순을 알렸는지와 무근거 주장을 넣었는지만 바꾼다.
**24가족·48사례나 기존 측정 3의 11건 분모에 더하지 않는다.**

### 독립 검토가 필요한 것

- 주문 원본과 질문·값·단위의 대응, 허용 계산의 의미.
- 모호함을 인정하는 답이 질문에 충분한지.
- 적용 조건이 다른 정상 정책과 실제 상충 정책의 구분.
- 출고 전 취소의 환급 기한을 현 정책으로 알 수 없다는 라벨.
- 개인정보를 제외한 상품 확인 답변의 허용 범위.

manifest의 `review_status`는 작성 출처와 검토 대기 상태만 기록한다.
무료 검사 통과로 이를 승인으로 바꾸지 않는다.

## 3. 무료 대조

```bash
uv run python -m scripts.check_evaluation_pilot
```

이 명령은 개발자 `.env`를 읽거나 DB·모델에 연결하지 않는다. 자료 구조·쌍·분할·원본 버전을
검사하고, 개발 묶음의 L1을 직접 실행하며 SQL은 현재 가드까지 확인한다.
정책/L2/자유 한국어 내용 정확도와 실제 SQL 실행은 수행하지 않았으면 `null`과 사유를 남긴다.
fixture에 적힌 정상/결함을 읽어 그 수를 “모델 검출률”로 출력하지 않는다.

SQL 결과 대조와 확인 절차는 **소유권을 확인한 일회용 DB**에서 검사한다.
개발 DB의 `app_conn`은 선행 시딩을 commit하므로 본문 rollback으로 보호되지 않는다.
전체 검사나 DB 검사를 기본 개발 설정으로 실행하지 않는다. 컨테이너 이름·발급한 임시
자격·loopback 포트·DB 이름·수명 상한을 함께 고정하고 종료 시 본인이 만든 컨테이너만 정리한다.

J11 네 상태의 무료 확인은 L1 통과와 실제 L2 파서가 기대 JSON을 해석할 수 있는지까지다.
파서가 기대값을 받는다는 사실은 L2 모델이 그 값을 생성한다는 증거가 아니다.

## 4. 유료 실행 전에 보존할 근거

실행 추적은 사례별 append-only JSONL로 남기는 것을 계약으로 정한다.
이번에는 **유료 호출·추적기 배선·새 승격을 구현하거나 실행하지 않는다.**
아래는 다음 유료 실행이 준비됐는지 검토할 수 있는 최소 보존 규약이다.

| 구간 | 보존할 것 |
|---|---|
| 실행 | 고유 run/attempt ID, 시작·끝 UTC, 코드 SHA, 모델·제공자·설정·응답 완료 상태, 조건 지문, 실행 완주 여부 |
| 입력 | case/family/split, 자료·라벨·원본의 SHA-256, 질문·확인 경로, 정답 검토 상태 |
| SQL | 생성 원문·실행 문자열·가드 판정, 조회 시점 원본 snapshot의 가림본, 결과 행·단위·유래, 독립 oracle 참조 |
| 검색 | 원문/재작성, 채택 전 순위·점수·모델 출처, 채택 ID와 본문 snapshot, 기권·컷·폴백 사유 |
| 초안·판정 | 모든 시도의 claim·citation, 공개 답변, L1/L2의 판정·각 사유·모순쌍, 제공자 원문 중 진단에 필요한 가림본 |
| 실패·비용 | 완료 전 실패 단계, 전송/형식 재시도 수, 미측정 구분, 계열별 토큰·캐시·지연, 단가 기준일 |
| 독립 채점 | 채점 기준 판, 사람/도구 식별·시각, 내용 오류·누락 조건·불필요 인계, 이견과 최종 처분 |

API 키·비밀번호·HMAC 원문은 저장하지 않는다. 실제 개인정보도 공개 평가 산출에 싣지 않는다.
가림으로 의미가 사라지는 값은 일관된 합성 토큰과 단위·관계만 남긴다. source ID나 해시만
남겨 실제 내용 재채점이 불가능해지는 것도 피한다.

부분 실행은 완료한 사례별 행을 먼저 보존하고, `completed/failed/interrupted`를 최종 manifest에
명시한다. 미완주를 완주 분모에 합치지 않는다. 한 시도의 실패가 이전 시도의 기각·비용을 지우지
않아야 한다. 파일 독점 생성, 원자적 완료 표시, 로컬 출력 가림 검증은 **다음 배선 작업의 조건**이다.

### 유료 실행 준비 판정

현재는 **준비 미완료**다. 아래가 충족돼야 별도로 비용 상한을 정해 실행할 수 있다.

1. 사람이 제안 정답과 취소/반품 경계를 검토하고 이견을 처분한다.
2. 보류 묶음의 노출 이력을 확인하고 평가 전에 자료·프롬프트·채점 기준을 고정한다.
3. 위 추적을 실제 호출 경로에 연결하고, 정상·실패·중단의 무료 대조로 누락을 검사한다.
4. DB가 이번 실행 소유임을 확인하고 과금 상한·중단 규칙을 정한다.

첫 전체 실행은 새 평가 모듈을 런타임으로 분류한 정답 격리 검사에서 실패했다.
채점자 등록과 런타임 접근 거부 대조를 함께 추가한 뒤 전체 검사를 다시 통과했다.
초기 mypy의 테스트용 함수 재참조 오류도 원래 모듈에서 직접 참조하도록 고쳤다.
원본 라이브 리포트·기존 평가 자료·승격 파일은 변경하지 않았다.

검증 과정에서 숫자 대조도 보완했다. JSON의 `3`/`3.0`은 같은 수치로, bool과 숫자는 다른
타입으로 비교하고, 큰 정수를 float로 반올림해 일치시키지 않는다. 무료 정합성 검사가
통과해도 manifest의 독립 검토 대기 상태는 유지한다.
