# 0028 — L2 산출 해석 규칙을 별도 지문으로 기록한다

- 날짜: 2026-09-30
- 상태: 채택. 사용자 요청으로 전체 리뷰의 잔여 결함을 해결하는 범위다.

## 문제와 선택

프롬프트가 같아도 parser가 미인용 모순쌍 기각을 수용하는지에 따라 형식 재시도·재생성·
인계와 비용이 달라졌다. 그런데 judge_prompt_version은 시스템 프롬프트 내용만 읽어 같은
값이었다. 기존 필드의 의미를 바꾸거나 프롬프트에 의미 없는 문장을 넣어 해시만 움직이지 않는다.

별도 judge_rule_version을 추가한다. 평가 모듈이 L2 JSON schema·허용 사유·형식 시도 상한
선언과 실제 공통 JSON 해석12개/L2 parser13개 경계의 결과로 내용 지문을 만든다. 진단 문구와
전체 소스 파일은 해시하지 않는다. 고정 탐침은 측정3 픽스처가 아니며 의미 정확도 분모에
더하지 않는다. 모든 Python 입력을 완전히 식별하는 지문이라고 주장하지 않는다.

## 과거 산출물과 승격

새 평가 CLI의 완성 지문은26칸, 필수 하한은24칸이다. 나머지 두 실행 항목은 generation_effort와
l2_enabled다. 2026-08-21 승격의 원본25칸은 그대로 둔다. 당시 파일에 새 항목을 쓰거나
과거 parser 값을 현재 코드로 추정하지 않는다.

과거의 새 값은 None/미상이다. 이미 등록된 파일끼리의 알려진 값 정합성 검사는 유지하므로
이번 확장이 역사적 등록을 자동 무효화하지 않는다. 기준선 대조는 미상을 병기하며 알려진
값으로 진행할 수 있지만, 그 결과를 모든 조건의 동일성으로 읽지 않는다. 새3회 세트 편입은
모든 조건이 알려져 같아야 하므로 과거 미상 산출물로 정족수를 채울 수 없다.

사이클5에서는 확장과 재등재를 함께 했다. 이번에는 과금·재등재 없이 누락된 축을 먼저
기록하고, 과거 축은 미상으로 남기는 대가를 명시한다. 승격/재등재는 여전히 사람만 한다.
기존 라이브 리포트·판정 프롬프트·평가 픽스처는 변경하지 않는다.

## 검증 경계

같은 프롬프트에서 parser 수용 여부를 바꾸면 지문이 움직이며, 공통 JSON의 NUL 수용·schema
선언·시도 상한 변화도 감지한다. 정상 입력도 지문에 기여한다. 설명 문구 변경만으로는
지문이 움직이지 않는다. 과거 누락은 미상, 신규 known 조건 차이는 선언 없는 대조 거부,
known 동일 조건만 세트 편입이라는 기존 구분을 함께 검사한다.
